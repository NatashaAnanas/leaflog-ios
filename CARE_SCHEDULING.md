# Расписание ухода

## Формулы
```
last = самая поздняя дата выполнения этого вида у этого растения (max, не «последняя внесённая»)
если расписания нет                → срока нет (только ручной учёт)
если есть last                     → due = startOfDay(last) + интервал
если last нет и якорь = firstDue   → due = startOfDay(anchor)
если last нет и якорь = lastCare   → due = startOfDay(anchor) + интервал   (запись в историю НЕ создаётся)
```
Интервал: `day` → `+N дней`, `week` → `+7N дней`, `month` → `Calendar.date(byAdding: .month)`.
Статус: `diff = дни(сегодня → due)`; `diff > 0` — через diff дней, `0` — сегодня, `< 0` — просрочено на |diff| дней.

## Примеры (проверены тестами в `SchedulingTests` и `RepositoryTests`)
| Случай | Результат |
|---|---|
| Интервал 7 дней, срок был 10 окт., полили 13 окт. | следующий — **20 окт.** |
| Интервал сменили с 7 на 10 дней, последний полив 13 окт. | 20 окт. → **23 окт.**; если срок уже прошёл — «просрочено» |
| Внесли запись «5 окт.» при существующей «13 окт.» | срок остаётся **20 окт.** (берётся max) |
| Удалили последнюю запись (13 окт.), осталась 5 окт. | срок пересчитан → **12 окт.** |
| История пуста, «последний раз 1 окт.», интервал 7 | **8 окт.** |
| Ежемесячно, 31 янв. | **28 февр.** (29 в високосный); 31 марта → 30 апр. |
| Ежемесячно, 28 февр. | **28 марта** (от фактической даты) |
| +7 дней через переход на летнее время (США, 7→14 марта) | 14 марта 00:00 по местному времени |
| Один и тот же момент в разных часовых поясах | срок и статус считаются в календаре текущего пояса, всегда на начало дня |

## Просрочка
Невыполненная задача остаётся **одной** задачей: исходный срок не меняется, растёт только счётчик «просрочено на N дней». Новые копии не создаются, события не фабрикуются.
Выполнение пересчитывает срок от фактической даты. «Отложить напоминание» — отдельное действие: меняет только `snoozedUntil`.

## Защита от дублей
`logCare` игнорирует повтор той же пары растение+вид в пределах 2 секунд и повтор с тем же `sourceKey` (действие из уведомления).
