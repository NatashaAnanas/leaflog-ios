# Архитектура

```
Leaflog/
  App/        LeaflogApp, RootView, AppEnvironment (зависимости), DemoData (изолированные демо-данные)
  Domain/     DateProvider, CareScheduling, NotificationPlanner, Season — чистая логика без UI и без SwiftData
  Models/     SwiftData-модели, схема V1, план миграций, предустановленные виды ухода
  Services/   CareRepository, TaskBuilder, NotificationService, PhotoStore, ImageProcessing, BackupService, AppSettings
  Tips/       локальный справочник советов
  Design/     Theme и общие компоненты
  Features/   экраны SwiftUI
```
UI не содержит бизнес-логики: изменения идут через `CareRepository`, расчёты — через `CareScheduler`/`NotificationPlanner`.

## Хранилище
SwiftData (`ModelContainer` в Application Support). Схема `LeaflogSchemaV1` + `LeaflogMigrationPlan` (пока без этапов; новые версии добавляют этапы, а не пересоздают базу).
Хранилище **не стирается** при запуске: при ошибке открытия показывается экран ошибки, данные остаются на диске.
Демо-данные доступны только в изолированной памяти по аргументу `-LEAFLOG_DEMO`.

| Модель | Назначение |
|---|---|
| `Plant` | растение: название, вид/сорт, архив, обложка, справочный профиль, свои советы, флаг уведомлений |
| `CareType` | вид ухода (встроенный или свой), цвет, иконка, включён ли. Не удаляется |
| `CareRule` | правило конкретного растения: интервал (день/неделя/месяц), якорь для пустой истории, snooze |
| `CareEvent` | факт ухода: дата, комментарий, `createdAt/updatedAt`, `sourceKey` (идемпотентность) |
| `PlantPhoto` | `addedAt` (неизменяема), `takenAt` (редактируема), подпись |
| `PlantNote` | текст, `createdAt/updatedAt`, `showsDate` |

План (правило), вид действия и факт — три отдельные сущности. События не ссылаются на правило, а следующий срок вычисляется, а не хранится; поэтому дубликатов и «фиктивных» событий нет.
Каскадное удаление: растение → фото, заметки, правила, события.

## Файлы изображений
`Application Support/Leaflog/Photos/<uuid>.jpg` (≤ 2048 px, JPEG 0.85) и `Thumbs/<uuid>.jpg` (≤ 480 px). Фото копируются из медиатеки/камеры; ссылок на оригиналы и временных URL нет.
Обработка (`ImageProcessing`) выполняется вне главного потока (ImageIO, `Task.detached`), миниатюры кэшируются в `NSCache` и декодируются фоном.
Порядок записи: файлы → запись в базе → при ошибке сохранения файлы удаляются. При удалении фото/растения удаляются файлы приложения (оригиналы в медиатеке не затрагиваются).
При запуске осиротевшие файлы убираются только после успешного чтения базы.

## Ошибки
`CareRepository.commit()` откатывает контекст при ошибке и бросает `LeaflogError.saveFailed`; экраны показывают сообщение и сохраняют введённые данные в `@State`. Успех не показывается, пока `save()` не прошёл.

## Время
`DateProvider(now:, calendar:)` подменяется в тестах. Все календарные вычисления — через `Calendar`, никогда прибавлением секунд.

## Справочник советов
`TipsCatalog`: 10 профилей (монстера, фикус Бенджамина, сансевиерия, замиокулькас, эпипремнум, спатифиллум, фаленопсис, алоэ, каланхоэ, хлорофитум) и общий профиль. Источники ориентиров: Royal Horticultural Society (rhs.org.uk/houseplants), Missouri Botanical Garden Plant Finder, ASPCA (токсичность). Тексты сформулированы самостоятельно; это общие ориентиры, а не копия баз данных. Строка за строкой с источниками они не сверялись — см. STATUS.
